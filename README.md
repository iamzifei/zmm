两套 AI 技能，装完说「**詹明明**」或输入 `/zmm` 就能进总入口：

| 套件 | 给谁 | 装完你会问它 |
|---|---|---|
| **📐 詹明明·内容操盘手** | 一个人自采自编的知识型创作者 | 「今天拍什么」「这稿子能不能发」「哪里会被划走」 |
| **📐 詹明明·小老板看盘** | 同时跑几条线的生意负责人 | 「这个月钱去哪了」「大客户会不会跑」「该投哪条线」 |

技能名就是你嘴里的那句话 —— 不用记英文，不用懂技术。
**套件名和技能名两层都带 `詹明明·` 前缀** —— 套件 tab 里认得出，
平铺的技能 tab 里跟别人的混在一起时也认得出。
下面两张表为了好读省掉了技能名前缀，只写功能名和命令。

装完之后，你用人话说你卡在哪，它会挑对的那个来处理。**只需要记一条命令：`/zmm`。**

第一次用，装完直接输入 **`/新手上路`**，它会一步步带你跑通一遍。

## 怎么装（完全没接触过 AI 也能跟着做）

> 下面每一步都可以**直接复制粘贴**。不用懂什么是「技能」「仓库」「终端」，照做就行。
> 如果哪一步卡住了，**把报错原样复制给 AI，让它帮你看**——这是最快的解决办法。

### 方式一：一条命令（最省事，支持 20+ 种 AI 工具）

```bash
npx skills add iamzifei/zmm
```

它会自动认出你在用哪个工具（Claude Code、Cursor、Codex、WorkBuddy、Windsurf、Gemini CLI…），
把 20 个技能装到对的目录。装完输入 `/新手上路`。

### 方式二：从技能市场装（WorkBuddy / OpenClaw 用户）

技能已上架 ClawHub，搜 **`詹明明`** 就能找到，也可以直接装：

```bash
npx clawhub install iamzifei/zmm          # 总入口
npx clawhub install iamzifei/zmm-topic    # 单个技能
```

全部 20 个在 **https://clawhub.ai/@iamzifei**。

WorkBuddy 用户在「专家·技能·连接器」里搜 `詹明明` 即可一键安装。

### 方式三：WorkBuddy 手动导入（不想敲命令）

WorkBuddy 是一个国内能直接用的 AI 助手客户端，装技能不用敲命令。

1. **下载安装 WorkBuddy**，打开它，登录。
2. 在电脑上**新建一个文件夹**，名字随便，比如 `我的AI技能`。记住它在哪（比如放桌面上）。
3. 把本项目**下载下来**：
   - 在本页面点绿色的 **Code** 按钮 → **Download ZIP**
   - 下载完**解压**，把解压出来的整个文件夹拖进刚才建的 `我的AI技能` 里
4. 打开 WorkBuddy 的**设置 → 技能（Skills）**，点「添加技能目录」，选中 `我的AI技能` 这个文件夹。
5. **重启 WorkBuddy**。
6. 在对话框里输入 **`/新手上路`**，回车。

看到它开始问你「你更想解决哪个」，就是装好了。

> WorkBuddy 的菜单名称可能随版本变化。**找不到「技能」入口就在设置里搜「skill」**，或者直接问 WorkBuddy 自己：「我要怎么添加本地技能目录？」

### 方式四：克隆仓库（会用终端、想改源码的人）

```bash
git clone https://github.com/iamzifei/zmm.git
cd zmm
bash install.sh          # 一条命令装完全部技能
cp config.example.yaml config.yaml
```

然后打开 Claude Code，输入 `/新手上路`。

### 方式五：其他工具手动放置

这些工具大多会读一个固定的技能目录。**通用做法**：

1. 找到该工具的技能目录（常见的是 `~/.agents/skills`、`~/.codex/skills`）
2. 把本项目 `skills/` 目录下的每个文件夹，**复制或软链**过去
3. 重启工具，输入 `/新手上路`

不确定目录在哪，**直接问那个工具**：「你的本地技能目录在哪？我要手动放一个技能进去。」

### 装完之后要填一样东西

技能需要知道**你是谁、你的红线是什么**，否则它不敢替你做判断。

1. 把 `config.example.yaml` **复制一份**，改名叫 `config.yaml`
2. 用任何文本编辑器打开，跟着里面的注释填
3. **不知道怎么填？** 直接对 AI 说：「帮我填 config.yaml，一项一项问我。」它会引导你

**没填也能用**，只是技能会明确告诉你「配置缺失，某些判断给不了」——**它不会拿默认值假装是你的设定**。

详细配置说明见 [SETUP.md](SETUP.md)。

## 这两套东西的共同点

市面上不缺内容生成器，也不缺商业框架。这两套的区别在三条硬规矩：

**1 · 没有数据就说没有，绝不编。**
每个判断都要能说出「这条从哪来」。缺数据标「无数据」，缺证据标「未经实证」，算不出来就说算不出来。填一个看起来合理的数比空着危险得多——**它会让整份分析失去可信度，而且你不知道是哪一处开始失真的。**

**2 · 从 TOP 榜单归纳出来的规律，一律不信。**
这套东西自己踩过：从某个对标账号的 TOP100 里归纳出「干货甜点区 1–2 分钟」，写进技能当硬约束；回到全量池 n=541 一验，**效应完全消失**。TOP 榜单是被结果筛选过的样本，从中归纳成功要素，等于只研究飞回来的飞机。

**3 · 结论会被自己推翻，推翻过程留在库里。**
`实证规律库` 里有降级记录、有负结果、有「测不出来」和「不成立」的区分。**一个只记成功结论的知识库是不可信的**——它没告诉你它错过几次。

## 📐 詹明明·内容操盘手（13 个技能）

给单人自采自编的知识型创作者。**主路径只有三步：**

```
选题 → 写稿 → 红线审核 → 发
```

**过了红线就可以发。** 其余七个是专项，卡住了才用，不卡就跳过。

> 这是硬规定不是建议。这套系统曾经有 7 道发布前闸门，结果是 13 条成稿、0 条发布——**闸门数量本身就是不发布的成因。**

| 技能 | 干什么 |
|---|---|
| **内容操盘手**<br>`zmm` | 入口：路由 + 导航 + 新手教程 |
| **今天拍什么**<br>`zmm-topic` | 选题：三条路（把判断走到死路 / 从事件找争点 / 借别人的题换自己的芯）+ 供需判定、认知落差、真实数据佐证 |
| **重讲一个概念**<br>`zmm-concept` | 重讲一个大家都在用的概念（定价 / 选题 / 需求 / 转化 / 获客…）——拆开它，从裂缝里长出一把尺子。先锁四样再写稿，最后由本人口述定稿 |
| **口播稿写作**<br>`zmm-script` | 写稿：从素材装配、逐段共创；也可只要开头 / 只要标题 |
| **发布前审一遍**<br>`zmm-review` | 发布前十二关：选题、开头、陌生化、信息清单、朋友与敌人、营销点、信息效率、筹码，再加具象度、结构断点、合规红线 |
| **发布后复盘**<br>`zmm-retro` | 复盘：真实数据回流、归因、写进记忆 |
| **口播剪辑**<br>`zmm-cut` | 口播成片剪辑技能（调用 ChatCut）。把拍好的口播素材剪成可发布的抖音成片：语音剪辑（去口癖/停顿/重复）→ 加速 → 字幕 → 交付 |
| **选题先试水**<br>`zmm-mvp` | 拿不准的想法，先花一条文本试水，别花一条视频 |
| **开头前五秒**<br>`zmm-hook` | 开头专项：先诊断内容有没有货，再按期待感三形式 + 信息缺口四法 + 走到死路出候选 |
| **哪里会被划走**<br>`zmm-flow` | 顺稿：逐段扫「哪一秒观众会划走」 |
| **戳不戳得中人**<br>`zmm-resonate` | 共鸣三模式：诊断自己的稿 / 拆别人的爆款 / 把「我觉得不对劲」升维成公共问题 |
| **标题与封面**<br>`zmm-title` | 标题封面：公式匹配，可追溯，过红线 |
| **公众号短文**<br>`zmm-post` | 公众号短文：标题 + 正文 + banner |
| **我该卖什么**<br>`zmm-product` | 产品提炼：把碎片化的经验和资源，变成一个能交付、能卖的东西 |

> `zmm-product` 是这一集里唯一产出**不是内容**的技能。放在内容集，是因为它的地基是自我开源：
> **内容侧说「区分度不来自更有用，来自你得出结论的路径」，产品侧一模一样** ——
> 抄竞品是抄结论，堆功能是以为「更有用」就是区分。
> **一个好的产品不是展示功能，是完成一次说服**，所以它本身就承担了一部分获客。

**红线在配置里，不在技能里。** 卖真口径、违禁词、不点名名单、文风、行业黑话禁令——全部读 `config.yaml`。**技能负责怎么判，配置负责判什么。**

### 技能启动时会去读什么

不是「凭印象写」。每个技能启动都按固定顺序读一批文件，读不到会**明说缺了什么、哪些判断因此给不了**，不拿默认值顶替。

以写稿为例，`zmm-script` 依次读：格式与钩子库 → **上一条的复盘数据 + 本条的要求文件** → 口播硬标准 → 语言风格档案 → 文案反馈规则库 → 已发布内容库（查重）。

其中第二项最容易漏也最贵：**它是唯一会随数据变化的输入。** 其余几周才动一次，它每发一条就变一次。

> 这条规则是赔出来的：一条口播稿连写两版共 4 分 13 秒，直到人工翻出复盘才发现同目录躺着一份要求文件，写着「60–90 秒单点」。两版全部作废。
> **规则文件不在加载清单里，等于它不存在。**

路径全部走 `config.paths.*`，你把 vault 放哪都行；`vault_root` 留空就是**无 vault 模式**，技能只做通用判断。

## 📐 詹明明·小老板看盘（7 个技能）

给**同时跑多条线的生意负责人**——开店的、做工厂的、带团队做 2B 的、做知识付费和电商直播的。

不是起盘工具（那是「怎么找到第一个客户」），不是大厂战略框架。是中间那段没人写的：**几条线都活着但都不够大，钱和时间该往哪投、哪条该砍。**

| 技能 | 独占问题 | 它最不一样的一条 |
|---|---|---|
| **该投哪条线**<br>`zmm-portfolio` | 几条线之间，资源怎么分 | **先找出真正卡住你的那样东西**（时间/现金/产能/铺位），再分配。任何「加码」都必须说清从哪抽——说不出来的加码建议是废话 |
| **这个月钱去哪了**<br>`zmm-revenue` | 钱的变化是从哪来的 | 拆成客户数 × 每客买多少 × 单价。**三种原因的处理动作完全相反**，不拆就有一半概率做反 |
| **大客户会不会跑**<br>`zmm-concentration` | 多少钱攥在极少数人手里 | **集中度越高，越不该主动去动他**。输出「禁止动作清单」，不输出「营销机会清单」 |
| **这生意靠谁**<br>`zmm-dependency` | 这门生意攥在谁手里 | 判据是「谁能不跟你商量就改变你的生意」。每个高危项必须算出换掉他要多少钱、多久——**给不出就是没评估** |
| **有什么到期了**<br>`zmm-track` | 在途与到期。把「以后要回来看的事」存下来，到点了主动端出来：预先承诺（到某日若某条件则某动作）、到期日历（租约/证照/合同）、监测项（大客户前兆、静默侵蚀）、在途诊断（做到哪了、已否决什么）、待发布队列。到期时只问条件满没满足，不重开辩论 | —— |
| **拿不准的时候**<br>`zmm-decide` | 这件事到底要不要做 / 我卡住了 | **把「拿不准」拆成三样**：不确定性（能查的去查）、风险（算最坏情况能不能承受，不是算概率）、机会成本（说不出具体的替代方案，那是舍不得不是成本）。三样分开，每样有各自的动作 |

三条贯穿全集的约束：

- **不假设你有系统**——对账单、订单本、微信收款、平台后台导出就够
- **不用向上汇报**——你就是拍板的人，直接给判断和动作
- **零术语**——理论照用，名词不出现

每个技能都带 `references/理论底座.md`，把每条判据挂到可查证的公开理论上（约束理论、现金转换周期、套牢问题、买方与供方议价能力、承诺机制、可证伪性、利特尔法则等）。**理论是脚手架不是权威**：你的实际数据和理论冲突时，以数据为准。

## 两套共用

**`zmm-track`** —— 在途与到期。

所有技能都会产出「到时候再说」的东西：到期日、复查点、待验证假设、预先承诺。**没有载体，它们全部等于没说过。**

核心规则只有一条：**到期时只问条件满没满足，不重开辩论。**

> 到期那天，你手里一定同时握着已经投进去的成本、一个「说不定下个月就好了」的信号、以及一个不想承认判断错了的自己。在那个时刻重新讨论条件，几乎必然是不执行。

所以承诺必须写成**可证伪**的形式。「如果还是不见起色」不算数，「到 12 月 31 日月营收仍低于 X」才算。**写不成可证伪的条件，就是没写。**

## 发布前

```bash
python3 scripts/leak_scan.py
```

扫身份、产品名、金额、账号密钥、本机路径。发现即非零退出，可以挂进发布流程。

它知道哪些目录该跳过（`docs/plans`、`docs/reviews`、`docs/runs` 是内部文档）、哪些文件允许保留敏感词（`config.yaml` 和它自己）。**用它，不要自己 grep。**

> ⚠️ 如果你把技能软链接到别处（比如 `~/.claude/skills/`），**在链接那一侧扫和改都会静默失效**：`grep -r` 默认不跟随软链接，返回「零命中」看起来像通过了；git 对软链接只存链接目标，在那边提交保存不了任何改动。**回真身目录操作。**

## 现状（不粉饰）

- 内容集的**数据回流闭环还没跑通过一次**真实的「发布 → 数据 → 归因 → 记忆」。它是设计意图，不是已实现的能力。
- `zmm-title` **没有爆款公式库**，因为实证没测出通用公式（12 种结构在两个风格互不相同的账号池上**零复现**）。它给的是方法和脚本，让你在自己的池子里现算。
- 部分信条标着「未经实证」——那不是「无效」，是**还没测出来**。两者不是一回事，库里明确区分。
- 内容集已经发布并复盘过**五条**真实短视频。样本仍然很小：由单条得出的约束（前 5 秒不给纯铺垫、最强的一句往前放、先测 60–90 秒单点）**在库里都标着 n=1**，写进规则是为了下一条能做对照，不是因为已经验证。
