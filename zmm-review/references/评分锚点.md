# 评分锚点

> `zmm-review` 的分数标尺光有定义不够——「什么叫 80 分」不给例子，每次评分都靠现场想象，结果就是跨评审员分歧。本文件用**真实成稿的句子**把四档钉死。
>
> **锚点必须来自自己的稿**。别人的句子锚不住自己的标尺，因为分数评的是「这句对我的观众有没有价值」，而观众是谁因人而异。
>
> 📦 **开源版说明**：本文件是模板。安装者应替换成自己 3–5 条成稿里的真实句子，替换前 `zmm-review` 的评分只能给参考区间，不给硬判定。

---

## 先分类，再打分（误伤防护，优先于一切）

**不是所有句子都参与信息密度评分。** 先归类，归错类再准的分也是错的：

| 句子类型 | 怎么处理 | 例 |
|---|---|---|
| **钩子句**（开头 1–2 句） | 不评密度，按开头三要素评（话题/Hook/可信度） | 「砸钱不一定能赚钱，但砸钱一定能让你更快看到结果。」 |
| **转场 / 框架宣告句** | 不评密度，按「有没有让人跟得上」评 | 「我把创业当成一张牌桌。规则就两条。」「这套规则你今天就能用，三步。」 |
| **金句 / 落点句** | 不评密度，按「能不能被单独记住并复述」评 | 「钱买不来成功，但买得来答案。」 |
| **CTA** | 不评 | 「关注我，带你把 AI 用明白。」 |
| **信息点** | ✅ 按下面四档评 | 其余全部 |

一条 100 秒的稿里，真正参与评分的信息点通常只有 12–20 个。**把转场句按密度打低分，是本技能最常见的误伤。**

## 四档锚点（全部取自真实成稿）

### 80+ ｜ 别处听不到的具体结论

判据：**含一手数据 / 一手发现，且具体到某个数值、某个场景、某句话。** 换个人来讲讲不出来，因为他没这个经历或没跑过这个数。

> 「同样是百分之十的成功率，他一年只能试一次，我能试六次。他还是百分之十，我已经接近一半。」

**为什么 85**：把一个抽象主张（速度=优势）变成了可验算的结论，而且数学是诚实的（1−0.9⁶≈47%，不是 60%）。观众能自己算一遍，算完就信了。这种句子别处听不到——不是因为难，是因为别人没算过。

> 「我做海外产品，第一天就开始投广告。投出去一块，回来六块。」

**为什么 80**：一手战绩 + 具体倍数 + 具体时点（第一天）。三个具体叠在一起。注意它**同时守了卖真红线**——给倍数不给金额。

> 「我一个月就知道了。不行，马上下桌，省下五个月，再开五个新的。」

**为什么 80**：具体到月份和后续动作，把「快」量化成了「省五个月、多开五个」。

---

### 60–79 ｜ 有价值的具体信息

判据：**可执行的具体动作，或把痛点收成一句话。** 有用，但换个懂行的人也讲得出来——不独家。

> 「上桌之前，白纸黑字写下你的下桌线：到什么数字算不行。」

**为什么 70**：动作具体到可以今天就做（写下来、写数字）。扣分点在于它是通用的决策卫生，不是这个人独有的发现。

> 「很多人恰恰做反了：赚钱的桌子，早早下来了；亏钱的桌子，舍不得走。」

**为什么 65**：把一个普遍错误收成了一句话，有画面。扣分点是这个洞察本身流传很广（损失厌恶的通俗版），观众多半听过。

> 「给你想试的事设一个验证预算。亏得起、又能看到真实结果的数，就是这个数。」

**为什么 62**：是动作，但「亏得起」这个关键量还是丢回给观众自己定义了——没给判据就够不到 70。

---

### 40–59 ｜ 真实但太常见

判据：**说的是真的，但所有讲这个话题的人都这么说**；或者概念对、没给例子。

> 「最难的不是第一步，是第三步。」

**为什么 45**：可能是真的，但没说**为什么**第三步难、难在哪、怎么办。留了一个坑没填。**这种句子最值得改**——它已经站在一个好洞察的门口了，补一句「因为到线的时候你手里正好有个看起来快成了的信号」就能上 75。

> 「感觉不算数，数字才算数。」

**为什么 50**：对，但太常见。它靠的是句式节奏而不是信息。

---

### <40 ｜ 废信息

判据：**删掉它，观众什么都不会少。** 排比凑节奏、重复上一句、自嗨、跑题。

> 「速度，有时候就决定了成不成。」

**为什么 35**：正确的废话。「有时候」把话说没了，「决定成不成」什么都没界定。它在钩子句后面重复了钩子已经说过的意思。

## 达标线怎么用（重要）

现行达标线是「≥8 句 60+ 且 ≥4 句 80+」。**但 60+ 计数已被双盲复测证明不可靠**——同一条基线稿两个独立评审员判 60+ 分别是 9 和 5，差 44%；而两人判 80+ 都是 0，且都独立指出了同一个天花板原因。

所以：

- **硬闸门只看两件事：≥4 句 80+，红线全过。**
- **60+ 计数只作参考**，写进报告但**不作 A/B 判据**——别拿「60+ 从 5 变 6」当改稿变好的证据。

理由见 `08-技能记忆/_通用/20260707-proxy分数信度-只信80加和红线.md`。

## 红线改写三段式

红线不是只标出来就完了，**要给可直接替换的成品**。格式固定为三段：

### 例 1 · 禁字系（死 / 杀 / 赌）

| | |
|---|---|
| **原文** | 「死就死在他舍不得下桌。」 |
| **触雷点** | 「死」字系。平台合规风险，且这类字在口播里会被字幕自动识别放大 |
| **改写** | 「他恰恰做反了——舍不得下桌。」 |

同系：「赌桌 / 赌场」→「牌桌」；「输」慎用；「杀」不用。
**这是成稿时主动规避，不是等自检兜底**（来源：`08-技能记忆/zmm-script/20260711-纠正-禁死字赌字系.md`）。

### 例 2 · 卖真（收入金额）

| | |
|---|---|
| **原文** | 「我投了 X 万广告，一个月回来 Y 万。」 |
| **触雷点** | 公域出现具体收入金额，撞卖真红线第 1 条 |
| **改写** | 「投出去一块，回来六块。」 |

**倍数口径是标准解法**：既保住了可信度（这是真数字的比值），又不露绝对金额。

### 例 3 · 绝对化词

| | |
|---|---|
| **原文** | 「这是最根本的原因。」 |
| **触雷点** | 「最」是违禁词表在列；且实测上绝对化词在抖音是负相关（R2，`实证规律库.md`，两个独立对标池 0.53× / 0.72×） |
| **改写** | 「这才是真正的原因。」／「这个原因经常被忽略。」 |

**这条要连效果一起讲给用户 听**——不只是「不让用」，是「用了数据也更差」。

### 例 4 · 编程词汇禁令（B 端向）

| | |
|---|---|
| **原文** | 「教你写个脚本自动跑。」 |
| **触雷点** | 钩子/前 30 秒出现编程词，B 端老板会自我排除 |
| **改写** | 「让 AI 每天自己把这活干了。」 |

例外见家族公约六：照念型（整句 prompt、工具名，观众只复制不理解）和以程序员为靶子的泛人群题。
