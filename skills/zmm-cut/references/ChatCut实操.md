## 一 · 环境检测与降级（🔴 装不上 ChatCut 也能干完一大半活）

### 检测

本会话第一次动手前，先跑一次只读定位（如 `get_active_project`）。三种失败：

| 现象 | 含义 |
|---|---|
| 工具根本不存在 | 没装 / 没连上 |
| 报 `signed out` | 装了但没登录 |
| 报打不开项目 / 项目不对 | 编辑器开着别的工程 |

### 告知下载（**照抄，不要自己编路径**）

> 打开 ChatCut 网页版并登录 → 点右上角头像 → 悬停 **Desktop App**
> → 按平台点 **Download**：**macOS Apple silicon** / **macOS Intel** / **Windows**

⚠️ **官方目前不提供 Linux 下载。**
⚠️ **不要凭记忆报版本号、价格、积分消耗。** 这些会变，要用时去查官方 Docs 当前页。

### 🟢 等不了就走本机旁路

🔴 **内容层的活全部不需要 ChatCut。**

```
本机 whisper 出文字稿（带时间轴）
  → 内容层重组的全部判断照做（废镜头、重复、重排、开场、接缝、一致性）
  → 产出一份「时间码 + 去留 + 理由」的剪辑方案
  → ChatCut 装好/登录后，只用来把方案落到时间轴
```

**这样做的两个好处**：不被环境卡住；**转写这一步不消耗云端资源**。

⚠️ **必须写实，不要夸大**：
**官方文档里没有「在 ChatCut 里选择本机模型」这个设置**（2026-09-05 查证 `docs/desktop-app`
与 `docs/transcript-and-captions`，两页都无此说法）。
上面说的是**技能自己在 ChatCut 之外跑本机模型**，不是 ChatCut 的功能。**不要说反。**

本机转写可用的现成方案（按可得性挑一个，不要写死）：
- `mlx_whisper`（Apple Silicon，快）· `whisper.cpp` · `faster-whisper`
- 要**词级时间戳**（判口误和做词级删除要用），跑的时候把对应开关打开

## 二 · 三个工具坑（都实测踩过）

### 坑 1 · `apply_script(preview:true)` 不是只读预览

**症状**：报错 `The timeline was modified by another tool or by the user`，
**但时间轴同时被改了** —— 而且改的内容**和你写的对不上**（stamp 过期导致行匹配错位，部分应用到了错误的行）。

🔴 **别用它当预览。** 正确做法：

1. `read_script` 拿**当前** stamp
2. 基于最新文件编辑
3. **直接 `apply_script()`** —— apply 保证**原子性（任一核心行出错整体回滚）**，比 preview 安全
4. apply 之后**必须读回来核对**，不要信回执的行数

**怎么取证是谁改了时间轴**：看**帧数**，不要逐行 diff。
`## V1 <!-- 0–NNNNf -->` 前后一比就知道删了多少秒，且不会被 ASR 文本变化干扰。

**怎么证伪「是不是转录变了」**：`library/*.md` 是**源转录，不受时间轴编辑影响**。
库里还在 = 是从时间轴上删的；库里也没了 = 转录真的变了。**查库比猜便宜。**

### 坑 2 · 改字幕样式会重新分页，Card id 当场失效

字幕卡的 id 是**内容哈希**。改**字号**或**框宽**会触发重新分页，
被合并/拆分的卡文字变了 ⇒ **id 变了**。

🔴 **危险在于它只错一部分**：文字没变的卡 id 不变，所以大部分调用还成功，**看起来像偶发**。

✅ **正确顺序**：**样式（字号/框宽/预设）全部定死 → 再读 id → 再上高亮。**
- 每次 span 操作返回**新 revision**，必须**链式传递**，不能复用旧的
- 报 `Card not found` 时先想「是不是重新分页了」，用**按帧读**（`atFrame`）单取那一张，比重读全部便宜

### 坑 3 · 被 `~~ ~~` 删掉的词，能靠写回库原文恢复

`[sN]` 行的「不许改写」约束的是**不许编造他没说过的话**，**不是不许还原**。

- ✅ 把该行写成**源库里的完整原文** → 还原
- ✅ 加一个 **bare `[sN]`** → 把该内容再播一次
- ❌ 改成他没说过的措辞 → 匹配失败

**动手前先 `grep` 库里那一行的原文，照抄。**
🔴 **不知道这条之前，会白白少一个修复手段**（试错成本为零：apply 原子，出错整体回滚）。

## 三 · 🔴 验收纪律：元数据会说谎

**实测三次被骗，共同点写成一条：**

> **行数、文字、画面，只能以全尺寸渲染帧为准。**

| 骗过我的 | 实际 |
|---|---|
| `read_captions` 报 `visualLineCount: 1 / overflow: false` | **渲出来折了两行** |
| 四宫格缩略图里看着字错了 | **全尺寸单帧渲染证明是我看错了** |
| 工具回执报「清理了 1 个词」 | **实际时间轴少了 147 帧（4.9 秒）** |

**每一大步之后固定验两样**：
1. **数字**：帧数 / 时长 / 段数 —— 和预期对不对得上
2. **画面**：渲**全尺寸**帧，不看缩略图下结论

⚠️ **缩略图只能用来做「挑哪一帧」的粗筛**，不能用来判对错。

## 四 · B-roll（用户明确要才做）

### 1 · 🔴 素材可信度：证言类素材必须先按时间/来源硬筛

B-roll 用来给口播里的**事实主张**做证言时，**用错的素材就是造假**。

**做法**：先确定那件事的**起始时间**，**早于它的素材全部排除**，不管多好看。
⚠️ 手机相册 / 下载目录多是**混合目录**，不是策划好的素材包。

✅ **实测**：38 个文件的目录里，按日期硬筛掉 12 个 —— 打开看，其中一张是完全无关的场景。
**硬筛之后还要抽样看图确认**，只看文件名不够。

### 2 · 公开发布含他人肖像：先打码

**判据不是法律，是常识**：他们是来参加活动的，不是来当内容素材的；平台分发范围不可控。

**做法（实测有效的那一版）**：

- ❌ **OpenCV Haar cascade 不够用** —— 空场景误检、人多的照片**漏掉一半以上正脸**。
  🔴 **打一半比不打更糟**：既没保护到人，看着还像事故。
- ✅ **YuNet**（`opencv_zoo` 的 face_detection_yunet ONNX）+ **多尺度切块检测**（整图 + 左右半幅 + 四象限），小脸才检得到
  ⚠️ GitHub raw 拿到的是 **Git LFS 指针**（约 130 字节），要走 `media.githubusercontent.com/media/...` 才是真模型
- 🔴 **马赛克强度判据**：**一张脸横跨 3 个块左右**才认不出。
  第一版按「框宽 ÷ 7」做，**原图并排一比仍然认得出**，返工。
- ✅ **必须做原图 vs 打码版的局部并排对照**，不能只看整图缩略图

🔴 **未打码的原图不要留在项目里** —— 那是自己引入的隐患，用完即删。

### 3 · 宽高比不匹配（横幅素材进竖屏画布）

**不要默认 cover**。16:9 裁成 9:16 只剩中间约 32% 的宽度，
**人群照裁完人就没了，证言就不成立了。**

✅ **两层做法**：前景 `contain`（完整不裁，居中）+ 背景放同一张放大铺满 **加高斯模糊**垫底。
比黑边好看，且信息一点不丢。

### 4 · 时长与位置

- **前 3 秒 / 后 3 秒不切走**
- 单次切走**约 2 秒**起步。⚠️ **停留久了很明显**，实测「每张 4–6 秒」被当场要求砍半
- **落点要对准关键词**，不是对准整句 —— 说「找场地」时给场地，不是说「定到礼拜四」时给
- 两处切走间隔**小于 1 秒**时合并成一段，否则口播画面只闪半秒

## 五 · 导出与最终验收

- 导出**分辨率 / 帧率**跟随时间轴，不要临时改
- **导出后验的是文件本身，不是编辑器预览** —— 抽 5–6 帧，确认字幕、高亮、B-roll、打码**都烧进去了**
- **核一次时长**：帧数 ÷ 帧率 = 导出文件时长，对不上就是有东西没渲进去

🔴 **默认交付「可编辑的时间轴」，不是成片文件。**
只有用户明确说导出 / 渲染 / 下载 / 要发布，才导。
