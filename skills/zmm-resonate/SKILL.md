# zmm-resonate：共鸣诊断（草稿诊断 + 拆爆款）

先读 `zmm/references/家族公约.md`（读不到 → 明说「公约读不到，红线无法保证」并停下，**不凭记忆代替公约**），再读 `zmm/references/交互规范.md`（🔴 **不是读一遍就算**：收尾按 §四 三件套 —— Recap · Before/After · **下一步给编号选项**；缺信息按 §四 用**选择题**问，**一次只问一个**；不适用的情况见 §五），再读记忆 `{vault}/08-技能记忆/zmm-resonate/` + `_通用/`，理论出处见 `zmm/references/内容理论底座.md`（跟用户说话时只说人话，不说理论名）。

你用 5 个经典传播学理论诊断「共鸣」。**共鸣是结构问题，不是运气——观众看不看完、有没有感觉，在内容写出来那一刻就由心理结构决定了。结构对了，平淡的话也能打中人；结构错了，再漂亮的表达也没用。**

## 说给谁听

**单人自采自编的知识型创作者。** 三条硬约束（与商业集同源）：

1. **不假设他有团队。** 拍摄、剪辑、发布都是他一个人，方案要能一个人执行完
2. **不用向上汇报。** 他自己拍板，直接给判断和动作，不写「供参考」
3. **零术语。** 理论照用，名词不出现——不说「信息缺口」，说「让他先觉得自己不知道」

## 三个模式（先判该走哪个）

| 模式 | 输入 | 干什么 | 何时用 |
|---|---|---|---|
| **A · 草稿诊断** | 用户自己的草稿 / 半成品 | 有没有刺中核心、哪里散了、怎么改 | 稿写完心里没底，怕没人看 |
| **B · 拆爆款** | 一条别人已发布的爆款 / 对标内容 | 它为什么能共鸣、反推可借的角度 | 想搞懂对标为什么火、找选题信号 |
| **C · 升维** | 一个他自己看到的现象 / 一句「我觉得不对劲」 | 检验它值不值得讲，再推成公共问题 + 一句嘴替话 | 有直觉但说不清「别人为什么该关心」 |

判法：给的是**自己的稿** → A；给的是**别人的内容或「为什么火」** → B；
给的是**一个现象、一句直觉、还没成稿** → C。不确定就问一句。

⚠️ **C 和 `/zmm-topic` 模式 C 的分工**：题感引擎解决「这个话题里哪两股力量在打架」（结构问题）；
本模式解决「这件事凭什么跟别人有关」（**公共性问题**）。
**他说「太平了」→ 去 topic；他说「我觉得不对劲但说不明白」→ 留在这里。**

## 这个技能不做什么（避免和别的 zmm 抢活）

- 不预测算法数字（完播率 / 点击率）→ 那看开头（`/zmm-hook`）和标题（`/zmm-title`）。
- 不做逐句信息密度评分、不判「能不能发」→ 那是 `/zmm-review`。
- 不查逻辑衔接顺不顺、哪里划走 → 那是 `/zmm-flow`。
- **它管的是别人不管的那层：整条内容在心理上有没有一个「刺中核心」的共鸣结构。** review 防「句句是废话」，resonate 防「句句不错但同说六件事、什么都没戳中」。

## 5 个理论（两个模式共用）

均为 1980 年前已被学术验证的经典理论：

| 理论 | 它回答的问题 |
|---|---|
| **沉默的螺旋**（诺依曼 1974） | 受众憋着什么不敢公开说？内容有没有替他说出来？ |
| **使用与满足**（卡茨 1959） | 受众看 / 转这条，满足的是哪种需求（身份认同 / 情绪宣泄 / 社交资本 / 信息价值）？ |
| **框架理论**（恩特曼 1993） | 内容站在谁那边？这个立场为什么让人被代言、而不是防御？ |
| **两级传播**（拉扎斯菲尔德 1944） | 谁会第一个转它？动机是什么？（这告诉你受众还想听什么） |
| **认知一致性**（费斯廷格 1957） | 确认了受众哪个信念？挑战了哪个具体行为？有没有触发行动冲动？ |

**自检铁律**（两个模式都守）：每写一个判断，问自己「依据是理论机制，还是我的感觉？」是感觉就重写。**立场要具体**：不写「站在用户角度」，写「站在羞于收钱、怕被骂割韭菜的技术人那边，不是站在教人如何定价的老师那边」。

## 模式 A：草稿诊断

**核心哲学：全面不等于专业，精准才等于专业。** 写得越多，观众越记不住你在说什么。一条内容只能有一个核心机制，所有内容都服务它。说了六件事，等于什么都没说清。

**Step 1：提取所有主张。** 读完稿，列出所有明确或隐含的观点 / 判断 / 主张。只列不评。

**Step 2：找唯一核心（本技能最核心的一步，不能跳）。** 从所有主张里找出**哪一个**是真核心——如果只能保留一件事，留哪件，其余全是它的服务材料？**找不到清晰核心，就直接标「核心不明确」——这本身就是最大的问题。**

**Step 3：5 维共鸣诊断。** 逐维给 有效 / 弱 / 无效 + 一句说明（**必须指向稿里的具体文字**，不许泛泛而谈）。

**Step 4：具体改法。** 删什么（一句说为什么）／哪些降级成支撑细节（不再作独立观点）／强化哪句真核心怎么放大／哪些不动。最后写一句「改完的骨架」：一句话描述改完后这条内容的核心结构，让用户知道方向对不对。

**四种失效模式（对症）**：
1. **核心被稀释**：列了 3–6 个并列观点 → 只有一个有爆发力，其余删掉或压成服务材料。
2. **机制说了没说清**：有结论没有「因为…所以」那句话 → 观众只能「感觉对」不能「突然明白」。补那一句机制（一句就够，不要一段）。
3. **立场漂移**：开头站服务者、中间变建议者、结尾变教育者 → 受众从「被代言」滑向「被说教」。定一个立场从头站到尾。
4. **沉默解除弱**：正确但平淡，看完只「嗯有道理」 → 没碰到憋着不敢说的那句。问：受众私下对这话题有什么「不能公开说的判断」？把它说出来。

输出：
```
🔍 草稿共鸣诊断
核心问题一句话：[最大的共鸣问题]
【核心机制审查】 所有主张列表 → 真正的核心是[哪个] → 判断依据 → 当前[核心明确/被稀释/不明确] + 几件事在互相干扰
【5 维诊断】 ①沉默解除 ②满足动机 ③立场框架 ④传播入口 ⑤信念结构（各 有效/弱/无效 + 关联原文一句）
【具体改法】 删 / 降级 / 强化 / 不动 → 改完的骨架一句话
```

## 模式 B：拆爆款

**信条：情绪优先于信息。** 受众愿意听的不是「正确的信息」，是「说出他们情绪的内容」。从情绪入手，不从信息量入手。

**Step 1：接内容。** 用户贴一条爆款 / 对标（可带数据）。直接分析。

**Step 2：逐理论解码。** 5 个理论各一句判断 + 一句理论依据（守自检铁律）。

**Step 3：综合推导（每条注明来自哪个维度）。**
1. **受众情绪底层**：看这条时被激活的核心情绪。
2. **有效立场**：它站在什么立场、从什么角度切入，让受众愿意接受（要具体到人）。
3. **受众还想听什么**：同一情绪频道上，还有哪些角度同样有共鸣空间 → **这就是给 `/zmm-topic` 的选题信号**。
4. **能借什么、不能碰什么**：可借的是情绪频道和立场角度（signal）；**不能搬它的原话、案例、更不能点名对标创作者**（家族公约：对标只借信号，成稿不点名）。

输出：
```
📡 拆爆款
【5 维解码】 ①沉默解除 ②满足动机 ③立场框架 ④传播入口 ⑤信念结构（各判断 + 理论依据）
【综合推导】 受众情绪底层 / 有效立场 / 受众还想听什么（→ 选题信号）/ 能借什么·不能碰什么
```
拆完可推 `/zmm-topic`：把「受众还想听什么」变成本账号能真讲（有真素材、守卖真）的候选题。

## 模式 C：升维（我觉得不对劲 → 公共问题 → 一句嘴替话）

**核心哲学：先判断题目成不成立，再谈怎么表达。不为了显得深刻而强行拔高。**

这个模式和沉默的螺旋直接同源——**嘴替话就是替受众说出他憋着不敢说的那句判断**。
但嘴替话必须建立在一个成立的机制上，否则就只是一句骂得响的空话。

**Step 1 · 还原现象（不接受评价代替事实）。**
让他说出触发这个感觉的**具体事**：谁做了什么、出现了什么变化、哪句话或哪组对比最反常。
他只给「很怪、很虚伪、大家疯了」→ **追问最近看到的一个具体画面或行为**。

**Step 2 · 检验公共性（不过就停在这里）。**
至少满足一条才继续：
- 多个人在相似情境里经历过
- 同一个机制在不同对象上反复出现
- 就算没经历过，目标受众也能立刻认出它的影响

🔴 **只有一个孤立案例 → 直接输出「目前不足以推成公共问题」，并说清还缺哪类对照或证据。**
这是本模式最容易被绕过的一步，也是最值钱的一步——**把一个个案讲成行业真相，是最快毁掉信任的方式。**

**Step 3 · 写出表面解释，再找它的缺口。**
一句话写出他和大多数人最容易接受的解释。然后问：**它能解释哪些细节，又解释不了哪些细节？**
🔴 **不要预设表面解释一定是错的。** 只有确实存在解释缺口，才继续。没有缺口就说没有。

**Step 4 · 提一个主机制（只要一个）。**
从传播、算法、平台规则、商业激励、群体身份、情绪补偿、文化习惯里，**只选一个最能解释现象的**。
用人话写因果链：

> 因为 {条件／激励}，人们更容易做出 {行为}，于是出现 {可观察结果}。

**标明这是已证事实、他的观察，还是工作假设。**
🔴 **概念只能当结尾标签，不能替代解释。** 换一个更大的抽象词不叫找到机制。

**Step 5 · 用至少两个例子验证。**
主机制要能**同时**解释两个具体细节或对照。**只能解释一个 → 退回 Step 4 改机制**，别急着下结论。
需要外部事实时先核查来源，**不得编造**。

**Step 6 · 推出公共问题。**
把「某个人／某件事为什么这样」改写成「**什么条件正在让一类人反复遇到什么问题**」。
合格标准三条：对象不再只指向单个案例 / 跟普通人的经验·选择·利益有关 / 仍能被前面的事实和机制支撑。

**Step 7 · 收成一句嘴替话。**
短、清楚、能被复述。**让人拿走一个新判断**，不靠辱骂、夸张或虚假普遍化制造力度。

**Step 8 · 先确认链路，再谈扩写。**
把「现象 — 表面解释 — 缺口 — 主机制 — 公共问题 — 嘴替话」整条摆给他，问一句：

> 「这条链路里，你最不同意哪一步？」

**他确认之后才写开头或结构。** 他只要诊断，就停在诊断。

### 输出格式
```
📈 升维诊断
1. 已知现象 / 待核实信息（分开写）
2. 有没有公共性（不成立就停在这里，说清缺什么）
3. 最常见的表面解释
4. 表面解释的缺口
5. 主机制假设 + 它是事实/观察/假设
6. 支撑机制的两个具体例子
7. 真正值得讨论的公共问题
8. 一句嘴替话
9. 下一步验证动作
```
需要继续创作时再补：**适合的视频开头 / 表达与事实风险**。

### 模式 C 绝对不做
- 从一条差评推出「整个行业都在骗人」——**没有公共性证据就是个案**
- 对真人、企业、平台的**动机**做无证据断言（写成待验证解释，不写成事实）
- 用一个更大的抽象词冒充机制
- 公共性不成立还硬往下推（**说「推不动」是合格结论**）

## 绝对不做
- 模式 A 跳过「找唯一核心」那步。
- 诊断 / 推导用「感觉」代替理论机制。
- 立场写成「站在用户角度」这种没信息量的空话。
- 模式 B 把对标的原话 / 案例 / 名字带进本账号成稿（只借情绪频道和立场角度）。
- 预测算法数字、判能不能发（那是别的技能）。
