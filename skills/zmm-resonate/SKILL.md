# zmm-resonate：共鸣诊断（观众带走了什么）

先读 `zmm/references/家族公约.md`（读不到 → 明说「公约读不到，红线无法保证」并停下，**不凭记忆代替公约**），再读 `zmm/references/交互规范.md`（🔴 **不是读一遍就算**：收尾按 §四 三件套 —— Recap · Before/After · **下一步给编号选项**；缺信息按 §四 用**选择题**问，**一次只问一个**；不适用的情况见 §五），再读记忆 `{vault}/08-技能记忆/zmm-resonate/` + `_通用/`，理论出处见 `zmm/references/内容理论底座.md` §七（跟用户说话时只说人话，不说理论名）。

**共鸣不是「写得好」，是观众看完手里多了一样东西，而且想拿它去做点什么。** 这两件事在内容写出来那一刻就定了，和运气无关。本技能只问这两件事：**他带走了什么？他会不会动手？** 理论只用来解释「为什么会这样」，退到脚注里。

## 说给谁听

**单人自采自编的知识型创作者。** 三条硬约束（与商业集同源）：

1. **不假设他有团队。** 拍摄、剪辑、发布都是他一个人，方案要能一个人执行完
2. **不用向上汇报。** 他自己拍板，直接给判断和动作，不写「供参考」
3. **零术语。** 理论照用，名词不出现 —— 不说「信息缺口」，说「让他先觉得自己不知道」

## 三个模式（先判该走哪个）

| 模式 | 输入 | 干什么 | 何时用 |
|---|---|---|---|
| **A · 草稿诊断** | 用户自己的草稿 / 半成品 | 观众能带走什么、会不会动手、哪里散了、怎么改 | 稿写完心里没底，怕没人看 |
| **B · 拆爆款** | 一条别人已发布的爆款 / 对标内容 | 它让观众带走了什么、为什么动手、反推可借的角度 | 想搞懂对标为什么火、找选题信号 |
| **C · 升维** | 一个他自己看到的现象 / 一句「我觉得不对劲」 | 检验它值不值得讲，再推成公共问题 + 一句嘴替话 | 有直觉但说不清「别人为什么该关心」 |

判法：给的是**自己的稿** → A；给的是**别人的内容或「为什么火」** → B；
给的是**一个现象、一句直觉、还没成稿** → C。不确定就问一句。

⚠️ **C 和 `/zmm-topic` 模式 C 的分工**：题感引擎解决「这个话题里哪两股力量在打架」（结构问题）；
本模式解决「这件事凭什么跟别人有关」（**公共性问题**）。
**他说「太平了」→ 去 topic；他说「我觉得不对劲但说不明白」→ 留在这里。**

## 这个技能不做什么（避免和别的 zmm 抢活）

- 不预测算法数字（完播率 / 点击率）→ 那看开头（`/zmm-hook`）和标题（`/zmm-title`）。
- 不做逐句信息密度评分、不判「能不能发」→ 那是 `/zmm-review`。
- 不查听感顺不顺、哪一拍划走 → 那是 `/zmm-flow`。
- **它管的是别人不管的那层：观众看完这条，手里有没有多一样东西，想不想拿它去干点什么。** review 防「句句是废话」，resonate 防「句句不错但同说六件事、什么都没留下」。

## 两张表：观众带走什么 · 观众会做什么（A / B 共用）

### 表一 · 三种收获（一条内容通常只能给一种，给全了等于没给）

| 收获 | 观众心里那句话 | 稿子上必须有的东西 | 没有它会怎样 |
|---|---|---|---|
| **原来是这样** | 「我之前想反了」 | 一个他没想到的因果：因为 X 所以 Y，一句就够 | 只有结论没有那一句「因为」，观众只能「感觉对」，记不住 |
| **我就说吧** | 「我早就觉得是这样」 | 把他私下已经信了、但没底气说的判断，用他给不出的证据坐实 | 只讲常识，看完「嗯有道理」，第二天忘 |
| **他替我说了** | 「这话我不敢说，他说了」 | 一句他在饭桌上憋着不说的话，稿子替他说出口，而且站在他这边 | 正确但安全，没碰到任何人不敢碰的地方 |

判据：**每一种收获都要能指到稿里的一句原文。** 指不到就是没有，不许用「整体感觉」补。

### 表二 · 四种冲动（各自独立，一种不推出另一种）

| 冲动 | 观众要拿这条去干什么 | 稿子里的触发物 |
|---|---|---|
| **收藏** | 以后要用 | 一个可以照着做的步骤、一张可以回头查的清单 |
| **转发** | 说明「我是这样的人」 | 一句转出去等于替自己表态的话（通常就是表一第三行那句） |
| **评论** | 有话要说 | 一个留了口子的判断：观众能补自己的例子，或能反驳 |
| **关注** | 想看他下一次怎么判断 | 判断方式露出来了，不只是这一次的结论 |

🔴 **四种冲动之间没有传递关系**：让人生气不等于让人同意，让人同意不等于让人转发，让人收藏不等于让人关注。每一种单独判，单独找触发物。

### 标注纪律（每条判断都要带）

写任何一条判断，分三层写，不许混：

- **原文**：稿里哪一句（引出来）
- **推断**：这句会让观众怎样（这是你的推断，不是事实）—— 后面标置信度 **高 / 中 / 低**
- **待验证**：观众是不是真这样，要什么数据才知道（评论区内容 / 转发比 / 收藏比 / 留存曲线哪一段）

情绪只能写成「这句可能让人 X」，不能写成「观众感到 X」。**推断写成事实，是这个技能最常见的失败。**

脚注：每条推断可在末尾用括号注明依据的机制（对应 `内容理论底座.md` §七 的编号），给用户看的正文不出现理论名。

## 模式 A：草稿诊断

**核心哲学：全面不等于专业，精准才等于专业。** 一条内容只能让观众带走一样东西，说了六件事，他一件也拿不走。

**Step 1 · 列主张。** 读完稿，把所有明确或隐含的观点 / 判断列出来。只列不评。

**Step 2 · 定唯一核心（本技能最核心的一步，不能跳）。** 如果只能保留一件事，留哪件？其余全是它的服务材料。**找不到清晰核心，就直接标「核心不明确」—— 这本身就是最大的问题。**

**Step 3 · 过表一：观众带走什么。** 对三种收获逐一问「稿里哪一句给了它」。有原文的写原文 + 推断 + 待验证；没原文的写「无」。**三种都无 = 核心有了但没落到观众手里**，这比核心不明确更常见。

**Step 4 · 过表二：观众会做什么。** 四种冲动逐一找触发物。找不到就写「无」，不硬凑。

**Step 5 · 立场核对。** 稿子从头到尾站在谁那边？写具体的人，不写「站在用户角度」—— 写「站在羞于收钱、怕被骂割韭菜的技术人那边，不是站在教人定价的老师那边」。**开头站服务者、中间变建议者、结尾变教育者** = 观众从「被代言」滑向「被说教」，表一第三行会失效。

**Step 6 · 改法。** 删什么（一句说为什么）／哪些降级成支撑细节／强化哪句让某一种收获落地／哪些不动。最后一句「改完的骨架」：改完后观众带走什么、想干什么。

**四种常见散法（对症）**：
1. **核心被稀释**：3–6 个并列观点，只有一个有力 → 其余删或压成材料
2. **有结论没因果**：观众只能「感觉对」 → 补一句「因为…所以…」，一句，不要一段
3. **立场漂移**：见 Step 5
4. **安全得没人记得**：正确、平淡、不碰任何人不敢碰的地方 → 问用户：受众私下对这话题有什么「不能公开说的判断」？把它写进去

输出：
```
🔍 草稿共鸣诊断
一句话：[观众看完手里有没有多东西；最大的问题是什么]
【核心】 主张列表 → 真核心是[哪个] → 依据 → 当前 [明确 / 被稀释 / 不明确]
【带走什么】 原来是这样 / 我就说吧 / 他替我说了 —— 各：原文 · 推断（置信度）· 待验证，或「无」
【会做什么】 收藏 / 转发 / 评论 / 关注 —— 各：触发物原文，或「无」
【立场】 站在谁那边（具体到人）· 有没有漂
【改法】 删 / 降级 / 强化 / 不动 → 改完的骨架一句话
```

## 模式 B：拆爆款

**先看它让观众带走了什么，再看它怎么说的。** 拆爆款最常见的错误是从表达技巧入手（「他用了反问」「他节奏快」），那些都是可以复制却复制不出效果的东西。

**Step 1 · 接内容。** 用户贴一条爆款 / 对标（可带数据：播放 / 点赞 / 收藏 / 转发 / 评论数，评论区样本）。直接分析。

**Step 2 · 过表一。** 它让观众带走了三种收获里的哪一种？指原文。**有数据就用数据交叉**：评论区大量「就是这样」「说到我心坎里」→ 偏「我就说吧」或「他替我说了」；「学到了」「原来如此」→ 偏「原来是这样」。没数据就标待验证。

**Step 3 · 过表二。** 四种冲动哪一种被触发了？**有数据时用比例判**：收藏 / 点赞高 → 收藏型；转发 / 点赞高 → 转发型；评论 / 点赞高 → 评论型。没数据只能写推断 + 待验证，不许写成结论。

**Step 4 · 立场与情绪频道。** 它站在谁那边（具体到人）；观众被激活的是哪种情绪（写「可能」，标置信度）。

**Step 5 · 可借的与不能碰的。**
- **可借**：情绪频道、立场角度、它让观众带走的那一种收获 —— 这是给 `/zmm-topic` 的选题信号
- **同一频道上观众还想听什么**：列 2–3 个同频道、本账号有真素材能讲的角度
- **不能碰**：它的原话、案例、结构原样搬；**更不能点名对标创作者**（家族公约：对标只借信号，成稿不点名）

输出：
```
📡 拆爆款
【带走什么】 三种收获各：原文 · 推断（置信度）· 数据交叉或待验证
【会做什么】 四种冲动各：触发物 · 数据比例或待验证
【立场与频道】 站在谁那边 · 激活什么情绪（可能，置信度）
【可借 / 不碰】 可借的信号 → 同频道还能讲什么（→ /zmm-topic）· 不能碰的清单
```

## 模式 C：升维（我觉得不对劲 → 公共问题 → 一句嘴替话）

**核心哲学：先判断题目成不成立，再谈怎么表达。不为了显得深刻而强行拔高。**

嘴替话就是表一第三行那句 —— 替受众说出他憋着不敢说的判断。但它必须建立在一个成立的机制上，否则只是一句骂得响的空话。

**Step 1 · 还原现象（不接受评价代替事实）。**
让他说出触发这个感觉的**具体事**：谁做了什么、出现了什么变化、哪句话或哪组对比最反常。
他只给「很怪、很虚伪、大家疯了」→ **追问最近看到的一个具体画面或行为**。

**Step 2 · 检验公共性（不过就停在这里）。**
至少满足一条才继续：
- 多个人在相似情境里经历过
- 同一个机制在不同对象上反复出现
- 就算没经历过，目标受众也能立刻认出它的影响

🔴 **只有一个孤立案例 → 直接输出「目前不足以推成公共问题」，并说清还缺哪类对照或证据。**
这是本模式最容易被绕过的一步，也是最值钱的一步 —— **把一个个案讲成行业真相，是最快毁掉信任的方式。**

**Step 3 · 写出表面解释，再找它的缺口。**
一句话写出他和大多数人最容易接受的解释。然后问：**它能解释哪些细节，又解释不了哪些细节？**
🔴 **不要预设表面解释一定是错的。** 只有确实存在解释缺口，才继续。没有缺口就说没有。

**Step 4 · 提一个主机制（只要一个）。**
从传播、算法、平台规则、商业激励、群体身份、情绪补偿、文化习惯里，**只选一个最能解释现象的**。
用人话写因果链：

> 因为 {条件／激励}，人们更容易做出 {行为}，于是出现 {可观察结果}。

**标明这是已证事实、他的观察，还是工作假设。**
🔴 **概念只能当结尾标签，不能替代解释。** 换一个更大的抽象词不叫找到机制。

**Step 5 · 用至少两个例子验证。**
主机制要能**同时**解释两个具体细节或对照。**只能解释一个 → 退回 Step 4 改机制**，别急着下结论。
需要外部事实时先核查来源，**不得编造**。

**Step 6 · 推出公共问题。**
把「某个人／某件事为什么这样」改写成「**什么条件正在让一类人反复遇到什么问题**」。
合格标准三条：对象不再只指向单个案例 / 跟普通人的经验·选择·利益有关 / 仍能被前面的事实和机制支撑。

**Step 7 · 收成一句嘴替话。**
短、清楚、能被复述。**让人拿走一个新判断**，不靠辱骂、夸张或虚假普遍化制造力度。

**Step 8 · 先确认链路，再谈扩写。**
把「现象 — 表面解释 — 缺口 — 主机制 — 公共问题 — 嘴替话」整条摆给他，问一句：

> 「这条链路里，你最不同意哪一步？」

**他确认之后才写开头或结构。** 他只要诊断，就停在诊断。

### 输出格式
```
📈 升维诊断
1. 已知现象 / 待核实信息（分开写）
2. 有没有公共性（不成立就停在这里，说清缺什么）
3. 最常见的表面解释
4. 表面解释的缺口
5. 主机制假设 + 它是事实/观察/假设
6. 支撑机制的两个具体例子
7. 真正值得讨论的公共问题
8. 一句嘴替话
9. 下一步验证动作
```
需要继续创作时再补：**适合的视频开头 / 表达与事实风险**。

### 模式 C 绝对不做
- 从一条差评推出「整个行业都在骗人」—— **没有公共性证据就是个案**
- 对真人、企业、平台的**动机**做无证据断言（写成待验证解释，不写成事实）
- 用一个更大的抽象词冒充机制
- 公共性不成立还硬往下推（**说「推不动」是合格结论**）

## 绝对不做
- 模式 A 跳过「定唯一核心」那步。
- 判断指不到原文还照写；推断写成事实；不标置信度。
- 用一种冲动推另一种（「会生气所以会转发」）。
- 立场写成「站在用户角度」这种没信息量的空话。
- 模式 B 把对标的原话 / 案例 / 名字带进本账号成稿（只借频道和角度）。
- 预测算法数字、判能不能发（那是别的技能）。
