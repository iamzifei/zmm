# 抓取手册（/zmm-benchmark 专用）

> 怎么把对标的内容真的拿到手上。**先判走哪条轨，再照着做。**
> 本文里标「实测」的都是 2026-09-03 用真账号真 key 跑出来的，标「未实测」的就是没跑过。

---

## 第 0 步 · 探测走哪条轨（开抓之前必做）

| 检查 | 怎么查 | 结果 |
|---|---|---|
| 能不能跑命令 | 试着执行 `python3 --version` | 报错 / 根本没有执行工具 → **B 轨** |
| 有没有 key | `echo $TIKHUB_API_KEY`，或看 `~/.env` 里有没有 `TIKHUB_API_KEY=` | 没有 → 先走下面的〈注册 TikHub〉 |

**豆包、WorkBuddy 这类没有终端的环境一律 B 轨**，不要让用户去装 Python。
两轨产出**同一份目录结构和同一份 meta 字段**，幕五的拆解不区分来源。

## A 轨 · 用 TikHub 自动抓

### 注册 TikHub（假设用户完全不懂技术，一步一步说）

**第 1 步**　打开 https://tikhub.io ，右上角「Sign Up」，用邮箱注册。收验证邮件点确认。

**第 2 步**　登录后进 https://user.tikhub.io ，左边找到「**API Keys**」。

**第 3 步**　点「Create API Key」，名字随便起（比如 `zmm`），**权限全选**（要用到抖音、小红书、视频号三块）。

**第 4 步**　生成后**立刻复制那串 key**——它只完整显示一次，关掉页面就看不全了。

**第 5 步**　把 key 存起来。在电脑上打开「终端」，粘这一行（把 `你的key` 换掉）后回车：

```bash
echo 'TIKHUB_API_KEY=你的key' >> ~/.env
```

脚本会自己去 `~/.env` 读，之后不用再管。
（也可以只在当前窗口临时用：`export TIKHUB_API_KEY=你的key`，关窗口就失效。）

**第 6 步**　充值。进 https://user.tikhub.io/users/add_credit 。

> 🔴 **实测（2026-09-03）：免费额度只够跑抖音。**
> 免费额度（$0.05）能调 `douyin/web/*` 和 `douyin/search/*`；
> **小红书（`xiaohongshu/app_v2/*`）和视频号（`wechat_channels/v2/*`）一律返回 402，明说「不接受免费额度」。**
> 只做抖音可以先不充；要做小红书或视频号，必须充值。
> 单价 $0.001/次请求（`calculate_price` 实测），**充 $5 ≈ 5000 次请求**，够扒上百个账号。

### 四条命令

脚本在仓库的 `scripts/benchmark_fetch.py`，**只用 Python 标准库，不需要 pip install 任何东西**。

> 🔴 **`--out` 一律写成 `{config.paths.benchmark}/对标-{账号名}`**（缺省即 `01-原始素材区/对标-某某`）。
> 下面为了好读写成了相对路径，**照抄会把整个对标库丢在当前目录**。

```bash
# ① 按方向找候选账号（抖音一次 30 个 / 小红书一次 20 个，各 1 次请求）
#    --limit 只能把这一页截短，调大没用（两个接口都不翻页）
#    视频号没有这个接口，见下面的限制
python3 scripts/benchmark_fetch.py search --platform douyin --kw "AI 副业"

# ② 先估成本，不花钱（--posts 填搜索结果里「作品」那一列的数字）
#    --dry-run 只算数、不建目录，--out 随便填一个名字就行
python3 scripts/benchmark_fetch.py list --platform douyin \
  --id <主页链接或 sec_user_id> --out "对标-某某" --dry-run --posts 600

# ③ 真的拉全量列表（默认最多 30 次请求，不够会明确告诉你）
python3 scripts/benchmark_fetch.py list --platform douyin \
  --id <主页链接或 sec_user_id> --out "对标-某某" --max-requests 40

# ④ 切三批 → 建目录 + 写 meta.md
python3 scripts/benchmark_fetch.py pick --out "对标-某某"

# ⑤ 下封面（加 --video 连视频一起下，很占空间，默认不下）
python3 scripts/benchmark_fetch.py media --out "对标-某某"
```

`--id` **直接粘主页链接就行**，脚本会自己把 id 抠出来。

### 各平台能做到什么（实测）

**三个平台都端到端跑通了**（2026-09-03，付费余额下实测）：

| 平台 | 搜账号 | 拉全量列表 | 封面 | 视频 |
|---|---|---|---|---|
| **抖音** | ✅ 一次 30 个，带粉丝 / 总赞 / 作品数 | ✅ 67 条 4 页拉全，与主页作品数一致 | ✅ | ✅ 无水印 mp4 |
| **小红书** | ✅ 一次 20 个，**只有粉丝数** | ✅ 57 条 3 页拉全 | ✅ | ⚪ 列表里没有播放地址 |
| **视频号** | 🔴 **没有这个接口** | ✅ 每页 15，实测 4 页零重复 | ✅ | 🔴 **加密，下下来放不了** |

三条硬限制，选平台前先知道：

1. 🔴 **视频号只能「已知账号再抓」。** 方向性搜索去抖音或小红书做，找到人再回视频号看他有没有号。
   它要的是 finder username（`v2_06000…@finder`），不是昵称也不是主页链接——
   用 `fetch_channel_id_to_username` 把主页分享链接里那个 `sph` 开头的 Channel ID 转过来。
2. 🔴 **视频号的视频是加密的。** 拿到的字节没有 mp4 的 `ftyp` 头，要用 `media.decode_key` 解。
   **脚本不做这件事**——解错了会写出一个放不了的文件，而完成度报告还会把它算成成功。
   `--video` 对视频号直接跳过并说明原因。要视频号的逐字稿，走 B 轨。
3. ⚪ **小红书搜索只给粉丝数**，还是缩写字符串（`Fans 21.6k`）。总赞和作品数要另外一个账号
   一次 `get_user_info`。脚本把拿不到的显示成 `—`，**不显示成 0**。

### 三个必须知道的数据口径（实测，别糊弄用户）

1. **三个平台都拿不到播放量。** 抖音的 `web/fetch_user_post_videos` 和
   `app/v3/fetch_user_post_videos` 都返回 `play_count: 0`（各查一整页 20 条）；
   小红书的 `view_count`、视频号的 `read_count` 同样恒为 0。
   **两个独立接口都是 0，说明不是选错了接口，是平台不给。**
   → 「数据最好的 10 条」**只能按互动总量排**：赞 + 评 + 藏 + 转。
   → 用户问「播放多少」时**直说拿不到**，不要拿点赞乘一个系数编出来。

2. **互动总量不加权。** 就是四项直接相加，不给转发乘 5、不给收藏乘 3。
   任何权重都是凭空发明的常数，没有东西验证过它。CSV 里四项分别列着，
   **哪一项撑起了这条视频，人自己看得出来。**

3. **收藏倾向 = 收藏 / 点赞**，不需要播放量就能算。
   这个比值高 = 内容被当成「要留着用的」而不是「看个乐」，是干货型内容最有用的信号。

### 会遇到的坑（都实测过）

| 现象 | 真相 | 怎么办 |
|---|---|---|
| 某一页返回 `{"status_code": 0}`，没有作品也没有 `has_more` | **上游随机返回空壳，而且照样计费。** 把它当成「列表到底了」会让 0-1 批静默变成假的 | 脚本已经对同一游标重试 4 次；仍失败就停下并标记列表不完整 |
| 报 `HTTP 400 / Request failed. Please retry` | 上游抽风。**接口回执里自己写了「本次请求不会被扣费」**（这是它说的，不是我测出来的） | 脚本自动重试 5 次 |
| 报 402 | 这个接口不吃免费额度 | 充值，或该平台改走 B 轨 |
| 封面/视频下载失败 | 抖音的图片和视频链接**带签名、有有效期** | 重跑一次 `list` 拿新链接再 `media` |
| 拉到的条数比他主页显示的少 | 列表没拉完 | 加大 `--max-requests` 重拉。**没拉完就在报告里写明 0-1 批不可用** |
| 小红书只拉到一页就停了 | 翻页游标挂在**最后一条笔记**上，顶层没有 | 脚本已处理（实测 3 页 57 条拉全） |
| 视频号 `up_continue` 一直是 0 | **它不是翻页标志**，有下一页时也是 0 | 脚本按「`last_buffer` 变了且这页非空」判断（实测第 2 页 15 条零重复） |

## B 轨 · 用「轻抖」手动提取

没有终端的环境（豆包 / WorkBuddy），或者用户不想碰命令行时走这条。

### 怎么用

1. 微信里搜小程序「**轻抖**」
2. 抖音里找到那条视频 → 分享 → 复制链接
3. 粘进轻抖 → 它会吐出**文案（逐字稿）+ 封面 + 评论**
4. 用户把文案粘回对话，你负责结构化落盘

同类小程序（轻抖抽风时的备选）：「视频解析助手」「短视频文案提取」之类，能力差不多，都有免费额度。

### 你要主动做的事（不要让用户一条一条硬扛）

- **先定顺序**：让他**只提取真正要用的那 30 条**，不要从头粘。顺序是：先爆款批（他主页数据一眼能看出来的那几条）→ 再最新批 → **最后 0-1 批（要往主页最底下翻，最累，但也最值钱）**
- **数据他手抄**：赞 / 评 / 藏 / 转，视频页面上都有。一条一行，格式随意
- **分批收**：一次收 5 条，收完给一次小结，别让他一口气粘 30 条
- **中位数怎么办**：B 轨拿不到全量列表 → **算不出全量分母**。
  🔴 **这时候硬规矩 2 依然生效**：不能因为拿不到分母就放宽结论。
  折中做法：让他**手抄主页最近 20 条的点赞数**（不用全部字段），用它算一个粗中位数，并在报告里标注「分母 n=20，非全量」。做不到就在爆款批的结论上一律写「n 不足，待验证」。

## 逐字稿（三档，让用户自己选）

| 档 | 怎么做 | 得到什么 | 代价 |
|---|---|---|---|
| **不做** | —— | 只能拆到标题 + 数据 + 封面层 | 拆不了结构、节奏、信息密度。**必须在报告里写明缺这一层** |
| **轻抖** | 粘链接直接出文案 | 完整逐字稿 | 30 条要粘 30 次 |
| **whisper** | `brew install whisper-cpp`，配 `--video` 下载的 mp4 批量转 | 完整逐字稿，自动 | 要装东西；转写有错别字和漏字 |

🔴 **三个平台都没有字幕接口。** 依据：把 TikHub 全部 1066 个接口按「字幕 / subtitle / caption / 转写」搜了一遍，
只有 YouTube 和 B 站有。**没有第四条路。**

## 封面大字（不要装 OCR）

`media` 下载的 `cover.jpg` **直接让 AI 看图读字**就行——多模态读封面大字完全够用。
实测：一张 323×430 的抖音封面，直接读出「365个赚钱小生意 / 1、小吃配方」，两行都对。
不要引导用户去装 PaddleOCR 或别的 OCR 工具，那是没必要的门槛。

读出来写进那条的 `meta.md` 的「封面大字」段。

> **为什么非要单独拿封面大字**：抖音的 `desc`（标题）是发布时打的字，
> 封面大字是烧在图上的。**观众先看到的是后者。** 两者经常不一样，混为一谈会得出错的标题结论。

## 风险告知（第一次要用到时说一次，说完等确认）

**必须原话说给用户，不要淡化：**

1. **抓取到的内容只用于你自己学习和拆解。** 二次发布、搬运、剪辑后重发，涉及著作权，风险你自己承担。
2. **成稿不要点名对方、不要搬原话和案例**（这是本系统的红线②，不是建议）。
3. **凡是需要你登录自己账号才能抓的路径**（部分接口的 cookie 参数、部分第三方工具要求扫码登录）：
   - 你的登录凭据会经过第三方工具
   - 高频抓取可能触发平台风控，轻则限流，**重则影响你自己的账号**
   - **能不登录就不登录。** TikHub 的抖音接口不需要你提供自己的 cookie，这也是优先走它的原因之一
4. **轻抖这类小程序需要微信登录**——它拿到的是你的微信身份，不是抖音账号。风险低于前一条，但仍属于「把凭据交给第三方」。

用户明确说「知道了，继续」再往下走。
