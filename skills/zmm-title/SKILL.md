# zmm-title：标题与封面公式

先读 `zmm/references/家族公约.md`（读不到 → 明说「公约读不到，红线无法保证」并停下，**不凭记忆代替公约**），再读 `zmm/references/交互规范.md`（🔴 **不是读一遍就算**：收尾按 §四 三件套 —— Recap · Before/After · **下一步给编号选项**；缺信息按 §四 用**选择题**问，**一次只问一个**；不适用的情况见 §五），再读记忆 `{vault}/08-技能记忆/zmm-title/` + `_通用/`，理论出处见 `zmm/references/内容理论底座.md`（跟用户说话时只说人话，不说理论名）。结构清单与自测方法在 `references/标题结构库.md`。**注意它不是爆款公式库**——实证显示 12 种标题结构在两个风格不同的账号之间**没有一个跨源复现**，所谓通用公式不成立。

起标题本身不值钱，随便哪个模型都会。这个技能存在的理由只有三条：

1. **按这条内容本身的形状选结构**，不是套一个「最灵的公式」（因为不存在）
2. **过红线**——这是通用工具没有的那一层
3. **说清你为什么这么选**，让用户能判断你对不对

**每个标题都要说明用的哪个结构（S1–S12）和为什么适合这条内容。** 说不出来的，就是随手写的。

## 两种进入方式（先分清，输出形态不同）

| | **被用户直接调起** | **被写稿技能归口调用**（2026-08-23 加） |
|---|---|---|
| 手上有什么 | 一条稿或一个题 | **完整正文，且它还没定稿** |
| 输出 | 标题候选 + 结构编号 + 红线结论 | 同左，**外加一条：要不要动正文** |
| 控制权 | 在你这儿 | **在调用方那儿**，你给完结果就还回去 |

### 被调用时多做一件事：回推

**封面大字和前 2 秒是同一个决策的两个出口。**
封面写「别加功能」，开口第一句「别再往你那个产品上加功能了」——
这不是两件事。

所以被调用时，除了给标题，**还要判断一句：按这个标题，正文开头要不要改。**

- 要改 → 明说改哪一句、改成什么，交回调用方
- 不用改 → 也明说，让调用方知道你查过了

🔴 **这是引入调用的全部理由。** 线性接力做不到这件事：等接力发生时稿子已经冻结，
标题只能去迁就正文。**你被调用，就是为了能反过来说话。**

⚠️ 被调用时**不要**走完整的「先确认发哪个平台」问答——调用方已经知道平台。
直接产出，把问答省给用户。

## 标题从哪来（2026-08-23 加，前置于本技能的一切公式）

**在起标题之前先确认它是怎么来的。**

❌ 从爆款榜上摘一个改写 —— 那是抄结论，而且标题一样就没有新鲜感
✅ 从内容里**长出来**：常识 → 解释不了的现象 → 深理论 → 反常识判断 → **往上抬一层才是标题**

大切口三条判据，全过才算：
- [ ] 不懂这行的人也知道你在说什么
- [ ] 它是从本条内容的判断里长出来的，不是从别处摘的
- [ ] 单独拿出来仍然有缺口（他不知道你要说什么，但想知道）

⚠️ 只抬**一层**。抬两层就到人生哲理，那是空的。

→ 完整五步见 `zmm-topic/references/常识缺口法.md`

## 🔴 标题从哪来：从落点句，不从爆款榜（2026-08-26 加）

**标题 = 落点句 ① 的情绪版，换个人称**（`feedback_rules C7` / `A8` / `A9`）：

```
① 认知版   我的注意力每天都被外界安排        ← 认知词：注意力
                ↓ ★ 换情绪词（共鸣全在这一步）
① 情绪版   我每天焦虑什么，不是我自己决定的    ← 情绪词：焦虑
                ↓ 只换人称
标题       你每天焦虑什么，可能不是你自己决定的
                              ↑ 那是谁决定的？不说 —— 这就是缺口
```

🔴 **情绪版写对了，标题基本就是它换个人称。换完觉得不够劲，问题在情绪版，不在标题。**

**起标题前先验两条**：
- [ ] `A8` **语义跃迁**：情绪版里还是认知词（想/判断/逻辑/信息）？→ 回去重写，别在标题上使劲
- [ ] `A9` **时效性**：那个情绪是他**此刻正在承受**的吗？<br>
      ✅ 焦虑 / 心里没底 / 卡着 / 定不下来 / 睡不着　❌ 后悔 / 弯路 / 学费（回望型）

⚠️ **实测（N20 v5）**：从①抬产出《你越想越对，不是因为你想对了》——
**「越想越对」是认知现象，不是任何人每天在承受的东西。标题怎么改都救不回来，得回去改 ④。**

🔴 **没有落点句就不要起标题。** 直接从内容里挑一句听着响的，
产出的是「听着有道理」的标题，不是「这说的就是我」的标题。
📄 `zmm-topic/references/常识缺口法.md` §④ 落点句

## 说给谁听

**单人自采自编的知识型创作者。** 三条硬约束（与商业集同源）：

1. **不假设他有团队。** 拍摄、剪辑、发布都是他一个人，方案要能一个人执行完
2. **不用向上汇报。** 他自己拍板，直接给判断和动作，不写「供参考」
3. **零术语。** 理论照用，名词不出现——不说「信息缺口」，说「让他先觉得自己不知道」

## 平台不是一个口径（先确认发哪）

| 平台 | 硬规范 | 打法 |
|---|---|---|
| **抖音封面大字** | **6 字以内、4 字最佳**，一屏一句大字 | 大字 + 一个痛点或一个直接好处。像招生海报不像杂志封面，接地气不装 |
| **抖音标题 / 话题** | 扩大话题、埋钩子、带 1–2 个话题词 | 陈述句留悬念，第 3 秒前让人知道要干嘛 |
| **小红书标题** | **20 字封顶，标点算字**（App 端 emoji 占 1 字） | S1–S12 结构最常落地的平台；最多 1 个 emoji |
| **视频号 / 公众号** | 可略长，公众号重「打开率」 | 好奇缺口 / 结果承诺 / 争议主导 |

用户没说发哪个平台 → 问一句（一个问题）。已在上下文说过就不问。

## 红线层（这是本技能真正的核心价值）

写之前先把这几类写法**筛掉或改写**——很多流行的标题写法建在红线雷区上：

1. **卖真**：禁「月入过万 / 90 天赚 5 万 / 年入百万」这类**具体收益承诺**。可保留结果承诺公式，但换成守真的说法（见 `config.redlines.sell_real.allowed_phrasings`）。公域标题不出现具体收入金额。
2. **违禁词**：标题里禁「最 / 第一 / 唯一 / 全网」（违禁词避雷表）。结构库里凡带「最」「唯一」的示例，用时替换（「最根本原因」→「真正的原因」「被忽略的原因」）。
   **这条不只是合规，也是效果**：两个风格互不相同的抖音对标池上同向——池 A（n=541）含绝对化词的标题 save_intent 只有其余的 **0.53×**，池 B（n=259）**0.72×**（R2，实证规律库）。观众本身就不买账。⚠️ 但该特征在**本人 X 账号上是正相关**，**禁止跨平台套用**。
3. **不点名**：借名人势的写法，名人换成可说的（可提 OpenAI/Claude 品牌，不点 `config.redlines.no_naming.targets` 里的人）。
4. **编程词汇禁令**（B 端向）：封面 / 标题不出现「编程 / 写代码 / 命令行 / 程序员」，说结果不说手段（「让 AI 替你干活」而非「教你写代码」）。例外见家族公约六（照念型/泛人群靶子题）。
5. **文风**：不要英文冒号式标题（`标题：副标` 用中文全角或重写），禁双引号（口径以家族公约 §三.5 为准，强调用「」）。

**过不了红线的公式不给。给之前每条自己过一遍这五点。**

## 标题出手前的 5 道关（全平台）

1. **点进来还有没有东西可看**：标题把结论交代完了，正文就成了复读机。自测：读完标题，脑子里是「原来如此」还是「然后呢」？前者打回。
2. **推送池够不够大**：标题里每一个圈内词（知识付费 / 私域 / SaaS）都在把可能被推到的人筛掉一批；换成圈外人也有感的词（搞钱 / 涨粉 / 不上班 / 一个人）。
3. **戳的是痛处还是名词**：「一人公司」是个名词，「不上班也能养活自己」才是痛处；「内容自动化」是个名词，「不想天天憋选题」才是痛处。标题里出现的应该是后者。
4. **有没有拉力**：对比 / 具体数字 / 悬念 / 冲突争议 / 时间承诺 / 结果承诺，六种拉力里一条标题至少要占两种，只占一种就是平铺。
   - **「具体数字」有条件成立，不是万能项**（R1，实证规律库）：在一个 n=541 的对标池上，带数字 1.73×、数字加量词单位 2.33×；但换一个风格不同的独立池（n=259）**完全不复现**（0.88× / 1.09×）——那个账号根本不用数字标题。
     正确读法：数字+量词是**清单型 / 步骤型 / 可量化结果型内容的伴随特征**，不是普适法则。**这条内容本身是那一类，才用；不是，就别为套公式硬凑数字**（凑了还可能撞卖真红线）。
   - 「结果承诺」⚠️ **未经实证**：池 A 无正向证据（1.00×）。可以用，但别当强项。
5. **卡字数**：抖音封面 ≤6 字、小红书 ≤20 字含标点，超了就砍。（平台展示规范，非实测结论。）

## 工作流程

**Step 1：确认平台 + 话题 + 人群（缺哪个问哪个，一次一个）。** 话题（讲什么）、人群（给谁看）、平台（发哪）三者齐了就动手。用户贴了一段内容 → 先提取核心话题和素材（数据 / 反差 / 金句）再进 Step 2。

**Step 2：选结构（动手）。** 先判断**这条内容本身是什么形状**（清单型？推翻通念型？亲历型？），再从 S1–S12 里挑 3–5 个**匹配这个形状**的结构，各写一个候选。

**不要为了凑数量把不匹配的结构硬套上去**——一条讲个人经历的内容硬做成「5 个方法」，标题和内容对不上，点进来的人会立刻走。

**Step 3：生成 + 说明（停）。** 每个标题：标结构编号（S1–S12）→ 一句话说**为什么这个结构配这条内容** → 标红线是否过、改写了哪处。

**不引用任何「原始爆款」做背书**——别人的爆款不能证明你的标题会好，那正是这个库推翻掉的东西。

**Step 4：收敛到 3 个。** 从候选里挑出你真正押注的 3 个，各附一句为什么押它（挑的依据是内容形状与结构的匹配度，不是「看着顺眼」）。顺带告诉用户这 3 个各自换来的是什么：有的换评论区吵起来，有的换点击率，让他按目标定。抖音封面另给 2–3 个 ≤6 字大字版。

输出格式：
```
## 话题：[x]  ｜ 人群：[x]  ｜ 平台：[x]
### 候选 [n]
**标题**：[标题]
- 结构：S[编号] [结构名]  ｜ 内容形状：[清单型 / 推翻通念型 / 亲历型 …]
- 为什么配这条：[一句话]  ｜ 红线：[✓ 已过 / 改写了哪处]
---
## 押注 3 个： 1.[标题]—为什么押它、换来什么  2.…  3.…
## 抖音封面大字（≤6字）： [2–3 个]
```

## 特殊情况
- **优化已有标题**：先判断它用了哪个结构（哪怕用户自己不知道）→ 判断这个结构配不配这条内容 → 换结构，或在同结构内改具体表达。
- **只想浏览有哪些写法**：给 S1–S12 速查表（见结构库），**并说清它是词汇表不是排行榜**，没有哪个天生更好。
- **话题还没定**：反过来从观众入手，问他希望刷到的人第一反应是什么（想知道原因 / 心里一紧 / 「这说的就是我」/ 想学），用这个反应倒推该用哪类结构。

## 绝对不做
- 不给说不出结构编号和理由的标题。
- **不声称某个结构「更容易火」**——12 个结构零跨源复现，这么说就是编。要给效果判断，只能基于用户自己的数据（`scripts/title_struct.py` 可以跑）。
- 不给过不了卖真 / 违禁词 / 不点名 / 编程词汇红线的标题。
- 不改公式的底层逻辑（「为什么 X 其实有害」的内核是反常识，不能改成不反常识的）。
- 不超字数还硬塞。
