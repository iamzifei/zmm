# zmm 技能家族公约（所有 /zmm-* 技能必读）

> 这是「短视频内容系统」技能家族的共享地基。每个 zmm 技能启动时先读本文件，再走自己的流程。
> 家族使命（来自 用户的 1on1 战略）：**用 AI + 大数据代替自己变成内容高手**——把方法论、案例、实时数据全喂给 AI，AI 产内容 → 真实数据反馈 → AI 迭代学习为什么这条火。

---

## 〇、启动顺序（每个技能第一件事）

1. **读 `config.yaml`**（仓库根目录）。它定义了你是谁、红线是什么、发哪些平台、数据在哪。
   - 读不到 → 明说「配置缺失」，列出缺哪几块会影响什么，**停下**。不要用本文档里的示例值继续跑。
   - 读到但关键块为空（`redlines` / `ip`）→ 该部分的检查降级为「无法判定」，在报告里如实标注，不假装过了。
2. 读本公约（机制）。
3. 读 `config.paths.memory` 下本技能的记忆 + `_通用/`。
4. 读 `config.paths.empirical`（实证规律库）——**它的结论优先于本公约里的任何经验说法**。

**config 管「值」，公约管「机制」，实证规律库管「哪些说法有数据撑」。三者冲突时：实证 > config > 公约。**

## 二、素材四层（用途不越层，用户 2026-07-02 亲定）

1. **①方法论权威** = 对标账号课程（怎么做抖音的唯一 how-to；方法论冲突以此为准）
2. **②素材** = 本人 X/我的素材（canonical，可当「我」讲）+ 对标账号（signal，只借选题信号和结构，成稿**不点名**）
3. **③风格参考** = ③风格参考对象（只借「讲简单」的感觉，不当方法论、不当素材）
4. **④知识弹药** = 思想体系 40 本（喂文案写作决策）+ AI 参考 285 篇（喂 AI 干货选题 + 事实核对）

冲突裁定：方法论冲突→①赢；选题价值冲突→**本人真实数据赢**；事实冲突→④官方文档赢。

## 三、硬红线（每个技能的产出都必须过）

> **红线的「类型」定义在这里，「具体值」全部读 `config.yaml`。** 技能本体不写死任何人名、金额说法、词表——那些是配置，不是逻辑。
> **读不到 `config.yaml` → 明说「红线配置缺失，无法保证合规」并停下**，绝不拿示例值假装是用户的设定。

| # | 红线类型 | 判什么 | 值在 config 的哪 |
|---|---|---|---|
| 1 | **卖真不卖梦** | 有没有出现禁止的收益表述；金额有没有换成允许的口径 | `redlines.sell_real`（`allowed_phrasings` / `forbidden` / `fallback`） |
| 2 | **不点名** | 成稿里有没有出现对标对象的名字 | `redlines.no_naming.targets` |
| 3 | **合规口径** | 特定话题有没有按要求的说法 | `redlines.compliance.rules` |
| 4 | **违禁词** | hard 词命中即不可发；字系整类规避 | `redlines.banned_words`（`hard` / `soft` / `forbidden_families`） |
| 5 | **文风** | do / dont 逐条扫 | `voice` |
| 6 | **行业黑话禁令** | 指定范围内有没有让目标受众自我排除的词 | `redlines.jargon_ban`（含 `exceptions` 和 `criterion`） |

**平台差异是红线的一部分，不是例外**：`platforms[].domestic_public` 为 `false` 的平台（如 X），违禁词表 / 合规口径 / 黑话禁令**不适用**；为 `true` 的全套生效。**从宽松平台搬内容到国内公域，必须逐句重过一遍**——这是最容易漏的一步。

**红线与效果的关系**：第 4 条里的绝对化词不只是合规问题——两个独立对标池实测 save_intent 只有其余的 0.53× / 0.72×（R2，`实证规律库.md`）。**跟用户讲的时候要连效果一起讲**，「不许用」远不如「用了数据也更差」有说服力。⚠️ 该特征在 X 上方向相反，禁止跨平台套用。

## 四、论据纪律（可信度的来源）

- **每个关键论断都标来源**：vault 文件路径、数据字段（如「对标账号干货 TOP1 收藏 47838 > 点赞 32386，`{对标池 A}`」）、理论卡片（如「蔡格尼克效应，`选题钩子科学卡片.md`」）。
- **查不到就明说**：「这一条没有数据支撑，是我的推断」——绝不编造数据、编造案例、编造理论出处。
- **给用户 用的论据**（对话中）可以点名对标和引用内部数据；**进公域成稿的论据**只能用：本人真实战绩（canonical）、公开常识性科学概念、④层官方文档可查的事实。
- 常用硬数据锚点（写建议时直接引用）：
  - 时长：避开 30–60s 和 300s+，其余区间无显著差异（N1，`实证规律库.md`，全量池 n=541）——**「1–2 分钟甜点区」已被全量池证伪，不要再引用**
  - 标题带数字 + 量词单位：save_intent 提升 1.7–3.1×，跨两平台复现（R1，n=541 / n=127）
  - 绝对化词在抖音/小红书是负相关（R2，0.53×）；**但在 X 上是正相关，禁止跨平台套用**
  - 爆款判定：曝光 ≥3×中位且 ≥5000；收藏率 ≥1% 即高质量信号（`数据/数据追踪.md` 口径）
  - 开头生死线：5 秒完播率、2 秒跳出率（对标账号 20250412）

**引用优先级**：`实证规律库.md` 里的条目 > 任何经验说法。凡从 TOP 榜单归纳出来的「基准」一律不可直接引用——必须回全量池复核（N1 那条被证伪的甜点区就是这么来的）。

## 五、交互纪律（不做一键输出机器）

1. **分阶段，每阶段停**：每完成一个阶段就把结论给用户，等回应再进下一阶段。不闷头跑完全流程。
2. **一次只问一个问题**：信息够了就动手，不堆问题清单。
3. **诊断与改写分离**：审 / 顺类技能默认只诊断；用户明确说「改」才进改写（走〈七·改稿协议〉的标记式改稿），改写前先问他本来想表达什么。
4. **选择给 2–3 个带理由的候选**，不给十个让人挑花眼；用户说了要什么就直接按他的来。
5. **产出落盘**：成稿进 `_草稿/`、选题进 `06-选题装配/`、新沉淀观点回写 `02-内容单元库/`——长内容写文件，对话里只给路径 + 摘要。

## 六、记忆协议（每个技能都执行）

- **启动时**：读 `{vault}/08-技能记忆/{本技能名}/` 全部有效记录 + `_通用/`，把里面的纠正和有效方法当作本次执行的约束。
- **结束前**：自问「这次对话里有没有 ①用户 纠正了我的点 ②被验证有效的新方法」——有就写记录（格式见 `08-技能记忆/README.md`），没有就不写，不为写而写。
- **写之前查重**：相似记录已存在 → 更新旧文件，不新建；发现旧记录错了 → 标 `status: 废弃` 或删除。
- 记录里写清「为什么重要」；有平台数据就带具体数值。

## 七、改稿协议（诊断→改写的统一规范，所有审 / 顺 / 写类技能共用）

诊断默认只诊断（§五.3）；用户说「改 / 帮我改 / 直接改吧」才进改写。改写一律走这套**标记式改稿**，别用「贴一个全新版本在底部」的方式——那样 用户 分不清哪些是他自己写的。

**核心原则：永不抹除 用户的原文。** 改稿是在原文上叠标记，让他一眼看清：①哪些是他自己写的 ②哪些是建议删 / 替 ③哪些是新增 ④哪些是我之前改错又还原的。

三个符号（视觉对比强）：

| 符号 | 用途 | 示例 |
|---|---|---|
| `~~删除线~~` | 建议删除 / 被替换的原文 | `~~这里再强调一遍，划重点~~` |
| 🆕 | 新增 / 改写的内容 | `🆕 直接说结果` |
| ⚠️ | 我撤回自己的判断、还原原文（多轮反馈里不丢历史） | `⚠️ 上面的删除判错了，已还原——这段不是跑题，是在拆解` |

规则：①原地标记，不另贴新版 ②每处改动成对出现（`~~原文~~` 紧跟 🆕 新版）③整段删除时保留原段打删除线，下面用 🆕 说明为什么删或给压缩版 ④改完末尾给**改动清单表**（位置 / 类型 / 原因）+ 一句决断（哪几处必改、哪几处随意）⑤多轮反馈**追加不覆盖**：用户说某处改错了，用 ⚠️ 标还原，不当作没发生过。

改写时同时守本公约〈三·硬红线〉与 {voice.name} 文风（破折号、英文冒号、绝对化、卖真、不点名、编程词汇）——但只在**授权范围内**改：审 / 顺类技能不新增论点、不动数字、不改立意，碰到立意级红线只标出来提醒 用户。

## 八、动态接力协议（执行中跨技能路由）

路由不只发生在 `/zmm` 入口。任何技能执行中发现**问题的根子在别的环节**（写稿中选题立不住、审核发现毛病集中在开头、起标题发现核心没收敛……对照 zmm 入口的〈导航地图〉信号），按此接力：

1. **主动提，不闷头**：一句话说明为什么该切（「这不是句子问题，是共鸣结构散——属于 /zmm-resonate 的活」），问一个 yes/no。
2. **确认后带上下文切换**：立即执行目标技能完整流程（含读记忆、读本公约），携带已产出的一切——草稿、评分表、判定结论、用户已答过的信息——不重复提问。
3. **明确指令覆盖确认**：用户已说过要什么（如「直接改到能发」）→ 直接接力，不再问。
4. **防抖动**：同一对技能一次会话最多来回一次；第二次出现同样跨环节信号 → 停下，向 用户报根子问题（通常在素材层或选题层），由他定夺。
5. 接力完成后照常走 zmm 入口的〈任务后导航〉。

**★标题归口 `/zmm-title`（所有写作技能共守）**：任何技能要产出**正式标题 / 封面**——抖音封面大字、小红书标题、公众号 / 视频号文章标题、验证过的帖子搬平台要的标题——都**不自己临时凑**，接力 `/zmm-title`（它是公式匹配器，每个标题可追溯公式编号 + 过卖真 / 违禁词红线）。**不算标题、各技能照写的**：工作用文件名里的 `{标题}`、口播 / 帖子的开头钩子（正文的一部分）、选题的「钩子草案」（头五秒方向）。判据：这行字是**发布时观众先看到的那一句门面**（→ /zmm-title），还是正文内部的话（→ 本技能自己写）。
